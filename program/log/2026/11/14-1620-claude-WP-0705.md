## Decisions, risks or questions raised
- Record steps post through `action_type_service::invoke` (the governed
  `update_record`/`set_entity_values` path), NOT `workflow_service::apply_action`
  — the latter's `update_field` writes custom fields via a direct repo call that
  bypasses Business Rules, so it would not satisfy REQ-LANE-006's "obey Business
  Rules as a direct edit does". A lane write names an Action Type by name on the
  lane's object; a name the workspace has not defined is refused at run time.
  The warehouse demo's provisional action types (ADR-0025 decision 5) are not
  real Action Types and are out of this WP's editions (desktop + workspace only).
