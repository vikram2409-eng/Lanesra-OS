## Fixes found by testing (each its own commit, with the why)

1. **Draft save refused** (frontend agent's open item). `save_builder_lane`
   called `create_version`, whose one-draft rule refuses an existing
   draft lane — an author iterating on a draft could not save at all.
   Added `update_draft_version` (service) + `update_version_definition`
   (repo): the draft's definition is replaced in place after validation
   (id/object must match, version must be the draft's own). A draft has
   no compiled graph yet, so nothing a run depends on moves. The
   one-draft rule still holds. 3 new tests (iterate twice, still v1
   with one version; wrong-version refused; wrong-id refused).
2. **Demo P-11 false positive** (coordinator). The demo's `laneCheckRef`
   filtered out only standalone `'[]'` elements, so
   `record.lines[].qty_received` never matched the `lines` collection
   and the blueprint reported P-11 `unknown record field 'lines[]'`.
   Now strips a trailing `[]` per segment, mirroring the core's P-11
   resolver. The implementation was wrong, not the test.
3. **Stale frontend fixture** (coordinator). `features/lanes/` copy of
   `lane-wh-receiving.json` was still 12 steps — it drifted at WP-0716
   AC-5 when the lane gained `verify-supplier`. Synced byte-identical
   to the schema example (13 steps); fixed the two assertions that
   encoded 12 (blueprint step list, runner Verify-stage button count)
   and regenerated the blueprint snapshot.
