## Decisions, risks or questions raised
- **Behaviour change:** a webhook call for an agent or pipeline without an active webhook trigger now returns 403. Before, any `agents.trigger` client could run any agent (RAID I-14).
- **Upgrade:** each trigger's identity is the narrowest that keeps it working. If a schedule ran an admin-scoped agent, it already failed before, because a drained run had no actor. It now names the reason: the identity lacks Administrator. An Administrator can grant that on the identity.
- The upgrade fixture caught an identity-name collision: names were built from the first 8 characters of the trigger id, and two ids could share them. Names now use the full id.
