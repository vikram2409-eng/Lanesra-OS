# ADR-0001: Track the build program in the repository

- Status: Accepted (program owner, 2026-10-16, PR #492)
- Date: 2026-10-16
- Work package: WP-0001
- Requirements: — (program infrastructure)

## Context

The Agent Playground build is large (221 requirements, ~120 work packages, ~7 months proposed) and
will be built by several AI agents from different vendors, in turn and sometimes in parallel, plus
people. Agents do not share chat history. Each agent can read and write the git repository; not all
of them can reliably use the GitHub API, a project board or external tools (some third-party
connectors also fail in sandboxed environments).

## Decision

1. The repository is the single source of truth for the plan and its state, under `program/`.
2. Each work package is one Markdown file with YAML front matter (machine-readable fields) and a body
   (goal, scope, acceptance criteria, test plan, progress log). One file per WP keeps parallel edits
   from conflicting.
3. Requirements have stable IDs in `spec/REQUIREMENTS.md`; work packages and tests cite them.
4. `STATUS.md` is generated by `programctl` from the WP files and checked for staleness in CI.
5. Session logs are one new file per session, so they never conflict.
6. `programctl` uses only the Python standard library so every agent environment can run it.

## Alternatives considered

- **GitHub Issues and Projects only.** Good board UI and notifications, but not readable offline or
  by agents without GitHub API access, not versioned with the code, and history of edits is weak.
  May be added later as a one-way mirror (RAID Q-04).
- **One big tracker file (YAML or Markdown table).** Simple, but every agent edits the same file →
  constant merge conflicts.
- **External tools (Linear, Jira, Notion).** Not reachable by every agent; splits truth from code.

## Consequences

- Tracker updates are commits and go through review like code.
- Agents must follow the protocol; CI enforces format, coverage and STATUS freshness.
- A web board view needs either GitHub's Markdown rendering of STATUS.md or a later mirror.
